# F8Goals — 双击 F10 呼出的极简全屏目标管理

打字即新建，回车即创建，点方块即完成。全屏大字，只有目标本身，没有多余 UI。
界面支持英文 / 中文——配置面板 → **语言** 一键切换，即时生效（含菜单栏菜单）。

## 操作

| 操作 | 效果 |
|---|---|
| **双击 F10** | 呼出全屏覆盖层（整体淡入） |
| **单击 F10 / Esc** | 收起，切回之前正在做的事（0.26s 渐隐） |
| 直接打字 + 回车 | 新建目标，出现在列表最下方（紧贴输入栏） |
| 直接打字 + **⌘+回车** | 新建目标并**直接按「默认时长」武装**（跳过 ⌘T 时长选择） |
| 输入框空 + 选中目标，按**回车** | 勾掉选中的目标（和点方块一样：淡出，淡出中可撤销） |
| **勾掉目标后** | 选中光标自动挤到**上一条目标**上（没有上一条就下一条） |
| 点击方块 | 勾选完成：淡出至消失（0.55s）；淡出中再点 = 撤销 |
| 点击目标文字 | 行内编辑（回车保存；清空后回车 = 删除该目标） |
| Esc | 一级：退出选中/子目标态；二级：取消编辑 / 清空草稿；三级：收起覆盖层 |
| **← / →** | 切换画布（目标组）；仅在输入框为空且未在编辑时生效，否则正常移动光标 |
| **↑ / ↓** | 移动选中的目标（同样仅在输入框为空且未在编辑时生效） |
| **Tab / Shift+Tab** | 见下方「子目标」 |
| **⌘T** | 展开/收起时长选择，给下一条新目标（或选中的已有目标）挂倒计时 |
| **回车 / Esc**（签到弹出时） | 回车 = 记录反馈并结束目标；Esc = 继续并**全屏重选时长** |
| **⌘.** | 呼出/收起配置面板（覆盖层已经开着时）；也可以走菜单栏 → Settings… |
| 菜单栏图标 | Show / Hide、Settings…、Quit |

双击判定窗口 0.45s。数据实时写入
`~/Library/Application Support/F8Goals/goals.json`（已勾选目标保留在文件里留档）。

## 倒计时 + 强制签到

给目标挂一个倒计时，到点后应用会**自己弹出来**，逼你处理这条目标——不是提醒，是打断。
专门为 ADHD 场景设计：拖延往往不是不想做，而是「过一会儿再看」的那个「过一会儿」永远不来。

**武装**：输入栏右侧一直有个表盘图标（没挂计时器时暗淡，挂了之后亮起显示分钟数），
点它或按 **⌘T** 展开一排预设（Off / 5m / 15m / 25m / 45m），左右键选、回车确认，
再打字回车才真正创建目标——两次回车分别管两件事，不会一次回车就把还没选好的时长定下来。
选中一条已有目标时按 ⌘T，武装的是那一条本身，不是「下一条新目标」。

**到期**：后台每 5s 扫一遍有没有目标过期，不是给每个目标各挂一个系统定时器——那种在
Mac 睡眠时不会触发，醒来后补不回来；轮询靠比较墙钟时间，睡多久都不影响醒来后判断对错。
到期时会自动呼出覆盖层、切到对应画布；如果正巧在编辑别的目标，先落盘再弹，不会丢字。
同时到期几条也不会一起炸出来，一次只处理一条，处理完（≤5s 内）自动接上下一条。

**签到卡片**：目标文字 + **反馈输入框**（自动聚焦，打字即记录）。就两个键，没有快捷键，
不存在按键和输入冲突：

| 键 | 效果 |
|---|---|
| **回车** | 保存反馈 + 结束目标（勾选完成，走现有淡出退场） |
| **Esc** | 继续这个目标——按原时长重启计时，并弹出**全屏时长选择**重选（默认落在 3 分钟；←/→ 选、回车确认；再按 Esc 或点外面取消） |

反馈随目标永久保存在 `~/Library/Application Support/F8Goals/goals.json` 的 `feedback`
字段里；Esc 继续时**反馈草稿保留**，下次到期弹卡片时输入还在。

**退路**：签到没处理完时，单击 F10、菜单栏 Show/Hide 都不管用——这是「强制」本身要求的；
但 Esc（继续）和菜单栏 Quit 永远可用，不是真的把人困死。打开配置里的
「F10 dismiss check-in」可以让 F10 直接关掉签到卡片（不等于做任何动作），默认关闭。

**已知限制**：签到卡片弹出时如果前台正好是微信（WeChat），macOS 26 会拒绝后台 App
抢键盘焦点（新旧激活 API 都试过，系统级限制），此时打字会落进微信。**点一下卡片
即获得焦点**，之后输入正常；其他 App 前台时无此问题。

## 子目标

**只允许两层：顶层目标 + 一层子目标，一个平铺视图，没有分层/下钻**。子目标不能再有
子目标（Tab 只允许挂到顶层目标；旧数据里的第三层加载时自动挂回祖父目标）。

Tab 覆盖两种输入：

| 场景 | 按 Tab | 结果 |
|---|---|---|
| 输入框有字 | 缩进待建的这条 | 挂到选中行（顶层）或最后一条顶层目标下面，连续回车逐条加子目标 |
| 选中了一条顶层目标（↑/↓ 选） | 把它拆成几条 | 输入框缩进到它下面，连续回车逐条加子目标 |
| Shift+Tab | 退回顶层输入 | 清空当前的挂靠对象 |

挂靠对象一旦定下不会在创建后自动清空，所以能连续回车加多条；挂靠期间**父目标高亮**
（见下），输入栏本身也缩进一格，不再需要额外的文字提示。
**挂靠中按 ↑/↓ 直接切换挂靠对象**（在顶层目标间移动，父目标高亮跟着走）——不会产生
选中条，也就不会误触发「回车勾掉」。

**编辑子目标、或输入栏正挂靠某条目标（输入子目标）时，那条父目标会高亮**
（文字变主题色 + 左侧竖线亮起）——加上缩进，父子关系一眼可见。

## 画布（目标组）

目标按画布分组，默认有 `Personal` / `Work` 两块。左右方向键环形切换，切换时：

- 目标区交叉淡入淡出 + 顺着切换方向的 40pt 小位移（不做横向滑动——滑动要求所有画布常驻
  视图树，且各画布目标数不同、输入栏位置会打架）
- 背景极光跟着画布的 `hueShift` 转一点色相，组间颜色有微妙差异
- 屏幕上方短暂淡入画布名，1.1s 后淡出，帮助确认切换生效（尤其两个画布都是空的时候）

新增 / 改名 / 删除画布，以及色相选择，在配置面板里（⌘. 呼出）。

## 配置面板（⌘.）

**两条路都能打开**：覆盖层已经开着时按 **⌘.**；或者点菜单栏图标 → **Settings…**（这条在覆盖层
没开的时候也能用，会先呼出覆盖层再开面板）。⌘. 只在覆盖层可见时生效——应用是 accessory，
不可见时按键根本到不了它。

⌘. 是在 AppDelegate 的 `NSEvent` 本地监听里拦的，不是 SwiftUI 的 `onKeyPress`——
后者收不到带 command 的组合键（已实测：命令组合键被 AppKit 的 key-equivalent 通道吃掉，
`onKeyPress` 一次都不触发）。状态栏菜单的 `keyEquivalent` 也不行：菜单不在主菜单栏里时，
它的快捷键不参与全局分发。所以键盘走本地监听、鼠标走菜单项，两条路各自独立。

覆盖层内的一块，淡入盖住目标区，不开新窗口；数据单独存到
`~/Library/Application Support/F8Goals/settings.json`（跟目标数据生命周期不同，改配置不该碰
`goals.json`）。首次启动没有这个文件很正常——跟 `goals.json` 一样，第一次真的改动某项配置才会
落盘；文件不存在或损坏都会静默退回默认值，不会崩溃。

**倒计时签到**（本版最重要的配置项，面板里放在最前面）：

- Presets (minutes) —— 空格或逗号分隔的一串数字，回车提交；解析不出合法数字就还原成原值，
  不会留一个空列表（那样武装面板会没有可选的时长）
- Default duration —— 常用预设点选 + 自定义数字输入（1–180 分钟）；**⌘+Enter 新建目标
  用的就是它**，时长选择里对应的预设块右上角有亮点标记
- Auto-arm new goals —— 打开后每次呼出覆盖层，只要当前没有别的武装状态，
  自动挂上 Default duration，不用每次手动 ⌘T
- Keep armed after creating —— 打开后建完一条目标不会自动卸下武装状态，
  连续新建的几条会共用同一个时长
- Esc / F10 dismiss check-in —— 打开后签到未决时 Esc、单击 F10、菜单栏都能正常收起
  （相当于直接关掉签到卡片本身），默认关闭

**Canvases**：每块画布一行，色相圆点点哪个换哪个（跟新画布自动分配用的是同一份色板），
名字是个可编辑的文本框，回车保存；最后一块画布不能删。

**Appearance**：呼吸背景、极光背景两个开关。极光关掉时退回一张静态渐变，连
`TimelineView` 都不起——实测这种状态下 CPU 是 0.0%（正常约 6-8%），不是简单地把动画调慢。

**Layout**：Input bar position（输入栏静止时的竖直位置）、Text size（目标文字/行高/
方块整体缩放）。Text size 是一个整体缩放系数，不是字号、行高、方块各自独立的滑块——
独立调很容易调出字比行高还高、方块和文字不成比例的破样子，这里又没法截图提前看出来拦住，
所以做成一个数就把所有比例锁住。两者都会实时影响正在开着的覆盖层。

**Language**：English / 中文 分段切换。所有界面文案（主界面、签到卡片、设置面板、菜单栏）
的单一来源是 `L10n.swift`，切完立刻全局生效，不需要重启；语言存在 `settings.json`，
旧文件没有这个字段时用 `decodeIfPresent` 兜底，不会重置用户已有的其他配置。

**History（历史）**：查看曾经完成的目标和签到反馈。数据不另存一份——直接读
`goals.json` 里 `isDone` 的目标（按完成时间倒序），反馈显示在目标下面；
点「历史 → 查看曾经的目标与反馈」进入，Esc / 返回按钮退出。

## 数据存在哪里

| 内容 | 位置 |
|---|---|
| 目标（含完成状态、计时器、**反馈**） | `~/Library/Application Support/F8Goals/goals.json` |
| 配置（时长预设、语言、外观、布局） | `~/Library/Application Support/F8Goals/settings.json` |
| v1 迁移备份（升级前的老数据） | `~/Library/Application Support/F8Goals/goals.v1.json` |

勾选完成的目标永远留在 goals.json 里留档，不删除——历史面板看到的就是这份数据。

## 布局与动效

动效一律只用淡入淡出，不做位移、缩放、模糊、错峰。

- **输入栏位置**：目标少时停在屏幕高度 58% 处（略低于正中，视觉重心更稳，配置面板里的
  Input bar position 可调，范围 35%-75%）；目标堆到要越过屏幕上缘时，列表区继续往下长、
  输入栏跟着下沉；沉到离屏幕底部还剩 56pt 就停住。
- **位置变化一律慢慢挪**：输入栏下沉/回升，以及某条目标消失后其余目标的移位，
  共用 `Motion.layout`（0.55s easeInOut），比内容淡入淡出慢一截。
- **装不下时**：只渲染放得下的最后若干条，更早的从顶部渐隐消失（遮罩渐变，不是硬切）。
  遮罩只在真的装不下时才挂——`mask` 会把内容裁到遮罩自身范围内，不需要渐隐就别裁，
  否则动画途中还没走到位的行会被切掉顶部的文字。区域高度恒 ≥ 行总高，保证行不会被裁——
  已用脚本验证过这条在 Text size 75%-135% 的全范围、不同目标数下都成立。
- **高度不靠测量**：区域高度 = 每行各自高度累加，全部算出来，不测量任何子视图。
  子目标行更矮，所以是累加不是「行数 × 单一行高」。
- **呼出**：窗口淡入 0.34s，内容同步淡入，时长共用 `Motion.Duration.reveal`。
- **收起**：窗口淡出 0.26s；等透明之后才复位内容状态，避免内容一边缩一边淡的拖沓感。
- **勾选**：整行淡出 0.55s 后从列表让位（JSON 保留记录），输入栏随之慢慢回升。
- **背景**：`MeshGradient` 九个控制点被慢速正弦扰动（幅度 16%-22%），配色是提亮过的
  蓝/紫/青色板——色块流动肉眼可见（此前幅度 5%-7% + 极暗配色，实测看不出动画）。
  15fps；覆盖层不可见时 `TimelineView` 暂停。实测 CPU：可见约 6-8%，隐藏 0.0%。
- **呼吸**：辉光透明度沿 7s 正弦在 **0↔0.26** 之间明灭（此前 0.030↔0.060，差 3% 肉眼无感），
  带一点蓝调更像极光；复用同一个 `TimelineView` 时钟，隐藏时一起暂停。

## 数据与迁移

磁盘格式是 v2：`{ schemaVersion, canvases, goals, activeCanvasID }`，取代 v1 的裸数组 `[Goal]`。
首次用新版本打开旧数据时自动迁移：原文件另存为 `goals.v1.json`（不影响你手动做的
`goals.json.bak`），已有目标全部归到新建的默认画布，UUID / 文本 / 完成状态 / 时间戳原样保留。

## 前提与自启

- 需要 **macOS 15 以上**（`MeshGradient` 等 API 要求）。
- 系统设置 → 键盘 → **「将 F1、F2 等键用作标准功能键」需开启**，否则 F10 是媒体键，热键不生效。
  选 F10 是因为 Firefox（F7 光标浏览）、VS Code（F8/F9/F12）、Excel（F9 重算/F4 绝对引用）均无冲突；
  想换别的键改 `Sources/F8Goals/HotkeyManager.swift` 里的 `kVK_F10` 即可。
- 开机自启：系统设置 → 通用 → 登录项 → 添加 `dist/F8Goals.app`。
- 退出：菜单栏图标 → Quit F8Goals（无 Dock 图标）。

## 设计要点

- **全局热键**：Carbon `RegisterEventHotKey(kVK_F10)`，无需辅助功能/输入监控权限。
- **覆盖层**：无边框窗口 + `.screenSaver` 层级 + 跨 Space，遮住菜单栏与所有应用，不打断底层 App。
- **动效单一来源**：所有曲线和时长集中在 `Theme.swift` 的 `Motion`，SwiftUI 与 AppKit 共用同一组时长，
  窗口淡入淡出和内容动画才不会是两个时钟。
- **不测量布局**：行高、输入栏高度是常量，区域高度由行数算出。之前用 `GeometryReader`
  量出高度再回填 `@State`，形成「内容高度 → 布局 → 内容高度」的回路，是画面抖动的根源。
- **入场纯推导**：行的透明度只由 `revealed` 推导，行内不存动画状态，每次呼出都能正确重播。
- **行位置显式定位**：行不靠 `VStack` 自然重排，而是 `ZStack` + `offset(y: -到底部的累加高度)`。
  交给 VStack 重排的话，位置变化没有可绑定的值，只能依赖外层 `withAnimation` 的环境事务，
  而行自己的 `.animation(_:value:)` 会把环境动画挡掉——结果就是某条目标消失后，
  其余目标瞬间跳位。显式定位后这个偏移量（CGFloat）本身成了可动画的值——和 v1.1 时用
  `Int` 的 indexFromBottom 是同一个技巧，只是泛化成累加不等高的行。
- **完成状态单一来源**：`completingIDs` / `retiredIDs` 两个集合 + `Motion.completion` 一个时长常量，
  收起时清空；不再靠 `Date()` 在计算属性里比时间。
- **多屏**：每屏一块覆盖窗口，并监听 `didChangeScreenParametersNotification` 在接/拔显示器后重建。
- **方向键有条件拦截**：`onKeyPress` 挂在覆盖层最外层（离实际聚焦的 TextField 很远），
  靠返回 `.ignored` 把键放行给输入框、`.handled` 消费掉。这依赖一个没有官方文档明确保证的
  行为——TextField 聚焦且有内容时，方向键是否还会冒泡到远处的祖先 `onKeyPress`——
  已用一个独立的最小 SwiftUI harness 实测确认会冒泡，才照这个方案实现。
- **画布切不做横向滑动**：改用 `.id(activeCanvasID)` 强制整块目标区换身份，配合
  `.transition(.asymmetric(...))` 做交叉淡入 + 顺方向位移；比真正的滑动便宜，也不需要
  所有画布同时留在视图树里。
- **Shift+Tab 已实测确认走同一个键**：在 `onKeyPress` 里，Shift+Tab 的 `press.key` 和纯 Tab
  完全一样（都是 `.tab`），区别只在 `press.modifiers.contains(.shift)`——不是 AppKit
  「backtab」那种独立键。同样用最小 harness 验证过，不是凭文档假设。
- **选中/子目标状态在收起、切画布时清空**：`selectedID` / `inputParentID` 是纯 UI 态，不落盘；
  收起时随 `resetTransient()` 一起清，切画布时单独清（否则会残留一个指向别的画布上
  某条目标的挂靠对象，Tab 再按下去就是指错对象）。
- **签到弹出时其余按键全部让路**：方向键、Tab、⌘T、⌘. 的 guard 里都加了
  `pendingCheckInID == nil`；`hide()` 自己也拒绝执行（不管是 Esc、单击 F10 还是菜单栏
  都走这一个函数，挡在这一处比在每个调用点各自判断更不容易漏）。`pendingCheckInID`
  故意不放进 `resetTransient()`，否则收起动画走完时会把还没处理的签到悄悄清掉，
  等于白做了「强制」这件事。配置里的「Esc / F10 dismiss check-in」打开后，
  `hide()` 和 `handleEscape()` 的这道 guard 会放行，但仅仅是关掉卡片本身，不触发
  Done/Snooze 等任何动作。
- **确认时长不靠拦截 Return**：选时长时第一次回车是「确认时长」、第二次才是「建目标」，
  这靠的是 TextField 自带的 `onSubmit` 回调自己判断 `isChoosingDuration`，不是用
  `onKeyPress` 去抢在 `onSubmit` 前面拦下 Return——onKeyPress 和 TextField 自己的
  Return 处理谁先谁后，文档没保证，干脆不依赖这个顺序。
- **签到快捷键放本地监听**：签到弹出时 `focusedField` 被清成 nil，SwiftUI 焦点链里没有
  任何聚焦元素，挂在外层容器上的 `onKeyPress` 收不到按键（用户实测失效）。所以
  D/K/S/X/1-4 和 Esc、⌘. 一样放在 AppDelegate 的 `NSEvent` 本地监听里，不依赖焦点链；
  动作执行统一转发给 OverlayView 的 `resolveCheckIn`，完成/延后/放弃的动画逻辑只有一份。
- **到期扫描用轮询比墙钟，不用 per-goal 的系统定时器**：后者在 Mac 睡眠时不触发，
  醒来后的补偿行为也不可靠；轮询只要「醒着的时候总会再 tick 一次」就能判断对错，
  跟睡了多久无关。已经端到端实测：注入一条已过期的计时器、冷启动整个 App
  （不带任何调试参数），等一次 tick 后覆盖层自动弹出、且正确切到了目标所在的画布。
- **配置改动即时生效，不用重启**：`SettingsStore.settings` 的 `didSet` 直接调用
  `save()`，配置面板里的控件基本都直接绑定 `$settingsStore.settings.某字段`——
  改一下、存一下、界面上该反映的地方立刻反映，中间没有「应用」按钮这一步。
- **极光关闭是真的不起动画，不是把它调不可见**：`AuroraBackground` 的 `meshEnabled=false`
  分支整个跳过 `TimelineView`，换成静态 `LinearGradient`；已实测这种状态下 CPU 是
  0.0%（覆盖层可见时），跟"隐藏覆盖层"的零耗一个量级，而不是仍在后台画只是看不出来。
- **尺寸可配置走参数传递，不走 SwiftUI environment**：`LayoutMetrics` 由
  `Settings.textScale` / `inputRestingFraction` 解析出来，作为普通参数一路传给
  `GoalRow`、`trimToFit`、行位置计算——不是塞进 `.environment(\.xxx)` 全局广播。
  这个 App 每块屏幕单独一个 `NSHostingView`，环境值跨窗口传递的边界情况没有验证过，
  显式参数是这个代码库从第一天就在用的风格，风险更小、也不用新學一套机制。
  `Metrics.contentWidth`（横向宽度）故意不参与这套缩放——缩放管的是竖直方向的
  行高字号，跟横向排版是两件事。默认值（scale=1.0, restingFraction=0.58）已用脚本
  核对过和重构前的硬编码常量逐项数值相等，加这个配置项本身不会让任何人的界面跳一下。
- 技术栈：SwiftUI 内容 + AppKit 窗口壳，SwiftPM 可执行目标，LSUIElement 后台常驻。
