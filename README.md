# F8Goals — 双击 F10 呼出的极简全屏目标管理

打字即新建，回车即创建，点方块即完成。全屏大字，只有目标本身，没有多余 UI。
界面文案为英文。

## 操作

| 操作 | 效果 |
|---|---|
| **双击 F10** | 呼出全屏覆盖层（整体淡入） |
| **单击 F10 / Esc** | 收起，切回之前正在做的事（0.26s 渐隐） |
| 直接打字 + 回车 | 新建目标，出现在列表最下方（紧贴输入栏） |
| 点击方块 | 勾选完成：淡出至消失（0.55s）；淡出中再点 = 撤销 |
| 点击目标文字 | 行内编辑（回车保存；清空后回车 = 删除该目标） |
| Esc | 一级：取消编辑 / 清空草稿；二级：收起覆盖层 |
| **← / →** | 切换画布（目标组）；仅在输入框为空且未在编辑时生效，否则正常移动光标 |
| 菜单栏图标 | Show / Hide、Quit |

双击判定窗口 0.45s。数据实时写入
`~/Library/Application Support/F8Goals/goals.json`（已勾选目标保留在文件里留档）。

## 画布（目标组）

目标按画布分组，默认有 `Personal` / `Work` 两块。左右方向键环形切换，切换时：

- 目标区交叉淡入淡出 + 顺着切换方向的 40pt 小位移（不做横向滑动——滑动要求所有画布常驻
  视图树，且各画布目标数不同、输入栏位置会打架）
- 背景极光跟着画布的 `hueShift` 转一点色相，组间颜色有微妙差异
- 屏幕上方短暂淡入画布名，1.1s 后淡出，帮助确认切换生效（尤其两个画布都是空的时候）

新增 / 改名 / 删除画布的界面还没做，在配置面板阶段一起上。

## 布局与动效

动效一律只用淡入淡出，不做位移、缩放、模糊、错峰。

- **输入栏位置**：目标少时停在屏幕高度 58% 处（略低于正中，视觉重心更稳，改
  `Metrics.inputRestingFraction` 可调）；目标堆到要越过屏幕上缘时，列表区继续往下长、
  输入栏跟着下沉；沉到离屏幕底部还剩 56pt 就停住。
- **位置变化一律慢慢挪**：输入栏下沉/回升，以及某条目标消失后其余目标的移位，
  共用 `Motion.layout`（0.55s easeInOut），比内容淡入淡出慢一截。
- **装不下时**：只渲染放得下的最后若干条，更早的从顶部渐隐消失（遮罩渐变，不是硬切）。
  遮罩只在真的装不下时才挂——`mask` 会把内容裁到遮罩自身范围内，不需要渐隐就别裁，
  否则动画途中还没走到位的行会被切掉顶部的文字。区域高度恒 ≥ 行总高，保证行不会被裁。
- **高度不靠测量**：区域高度 = 行数 × 常量行高，全部算出来，不测量任何子视图。
- **呼出**：窗口淡入 0.34s，内容同步淡入，时长共用 `Motion.Duration.reveal`。
- **收起**：窗口淡出 0.26s；等透明之后才复位内容状态，避免内容一边缩一边淡的拖沓感。
- **勾选**：整行淡出 0.55s 后从列表让位（JSON 保留记录），输入栏随之慢慢回升。
- **背景**：`MeshGradient` 九个控制点被慢速正弦轻微扰动，叠固定噪点消色带 + 暗角收视线。
  15fps 足够（扰动极慢，看不出差别）；覆盖层不可见时 `TimelineView` 暂停。
  实测 CPU：可见约 6-8%，隐藏 0.0%。
- **呼吸**：辉光透明度沿 7s 慢正弦起伏（0.030↔0.060），复用同一个 `TimelineView` 时钟，
  不额外起时钟、隐藏时一起暂停——默认状态下唯一的动，幅度压得很轻。

## 数据与迁移

磁盘格式是 v2：`{ schemaVersion, canvases, goals, activeCanvasID }`，取代 v1 的裸数组 `[Goal]`。
首次用新版本打开旧数据时自动迁移：原文件另存为 `goals.v1.json`（不影响你手动做的
`goals.json.bak`），已有目标全部归到新建的默认画布，UUID / 文本 / 完成状态 / 时间戳原样保留。

## 前提与自启

- 需要 **macOS 15 以上**（`MeshGradient` 等 API 要求）。
- 系统设置 → 键盘 → **「将 F1、F2 等键用作标准功能键」需开启**，否则 F10 是媒体键，热键不生效。
  选 F10 是因为 Firefox（F7 光标浏览）、VS Code（F8/F9/F12）、Excel（F9 重算/F4 绝对引用）均无冲突；
  想换别的键改 `Sources/F8Goals/HotkeyManager.swift` 里的 `kVK_F10` 即可。
- 开机自启：系统设置 → 通用 → 登录项 → 添加 `dist/F8Goals.app`。
- 退出：菜单栏图标 → Quit F8Goals（无 Dock 图标）。

## 构建

```bash
swift build -c release        # SwiftPM，无需 Xcode
./Packaging/package.sh        # → dist/F8Goals.app（ad-hoc 签名）
open dist/F8Goals.app
```

调试入口：`dist/F8Goals.app/Contents/MacOS/F8Goals --show` / `--hide`（启动后自动呼出/收起）。

## 设计要点

- **全局热键**：Carbon `RegisterEventHotKey(kVK_F10)`，无需辅助功能/输入监控权限。
- **覆盖层**：无边框窗口 + `.screenSaver` 层级 + 跨 Space，遮住菜单栏与所有应用，不打断底层 App。
- **动效单一来源**：所有曲线和时长集中在 `Theme.swift` 的 `Motion`，SwiftUI 与 AppKit 共用同一组时长，
  窗口淡入淡出和内容动画才不会是两个时钟。
- **不测量布局**：行高、输入栏高度是常量，区域高度由行数算出。之前用 `GeometryReader`
  量出高度再回填 `@State`，形成「内容高度 → 布局 → 内容高度」的回路，是画面抖动的根源。
- **入场纯推导**：行的透明度只由 `revealed` 推导，行内不存动画状态，每次呼出都能正确重播。
- **行位置显式定位**：行不靠 `VStack` 自然重排，而是 `ZStack` + `offset(y: -第几行 × 行高)`。
  交给 VStack 重排的话，位置变化没有可绑定的值，只能依赖外层 `withAnimation` 的环境事务，
  而行自己的 `.animation(_:value:)` 会把环境动画挡掉——结果就是某条目标消失后，
  其余目标瞬间跳位。显式定位后 `indexFromBottom` 本身成了可动画的值。
- **完成状态单一来源**：`completingIDs` / `retiredIDs` 两个集合 + `Motion.completion` 一个时长常量，
  收起时清空；不再靠 `Date()` 在计算属性里比时间。
- **多屏**：每屏一块覆盖窗口，并监听 `didChangeScreenParametersNotification` 在接/拔显示器后重建。
- **方向键有条件拦截**：`onKeyPress` 挂在覆盖层最外层（离实际聚焦的 TextField 很远），
  靠返回 `.ignored` 把键放行给输入框、`.handled` 消费掉。这依赖一个没有官方文档明确保证的
  行为——TextField 聚焦且有内容时，方向键是否还会冒泡到远处的祖先 `onKeyPress`——
  已用一个独立的最小 SwiftUI harness 实测确认会冒泡，才照这个方案实现。
- **画布切不做横向滑动**：改用 `.id(activeCanvasID)` 强制整块目标区换身份，配合
  `.transition(.asymmetric(...))` 做交叉淡入 + 顺方向位移；比真正的滑动便宜，也不需要
  所有画布同时留在视图树里。
- 技术栈：SwiftUI 内容 + AppKit 窗口壳，SwiftPM 可执行目标，LSUIElement 后台常驻。
